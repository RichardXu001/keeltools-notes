新站第一个月的 SEO：查收录比发文章重要

2026-10-23 · 约 7 分钟

新站上线的第一个月没有任何搜索数据，这时候最不该做的事是继续加文章。第一件正事只有一个：让搜索引擎能找到、抓得懂你想排名的每一页。

结论：第一个月的清单是验证三个站长平台、提交 sitemap、然后按周复查收录——管道通了，再谈内容节奏。

01 三个平台，一个都不能省

每个搜索引擎跑自己的站长后台，数据互不相通：Google Search Console 管 Google（验证属性 → Sitemaps 报告提交 → URL 检查单页收录状态）；Bing Webmaster Tools 管 Bing 与 Copilot（可以直接从 Search Console 导入，省一半配置）；面向中文受众再加百度站长。这一步没做，后面所有「为什么没收录」的问题都查不出答案——没有数据就没有诊断。

02 sitemap 与 robots 的最低配置

每个新站上线前的三个文件
文件作用常见错误
sitemap.xml把全部可收录页面告诉搜索引擎漏了新页面、包含 noindex 页
robots.txt声明抓取规则并指向 sitemap忘了写 Sitemap 行，甚至整个文件 404
页面 canonical每个 URL 指向自己，避免重复内容分权双语站漏了 hreflang 互相声明

一个容易被忽略的坑：静态托管的 404 不会报错，只会悄悄少收录。提交 sitemap 前把每条 URL 用 curl 打一遍，全部 200 再交——我们这个 GitHub Pages 笔记站就是这么自查的，第一轮就发现了 robots.txt 缺失。

03 收录要按周复查，不是按天

提交之后没有「立刻收录」这回事：新域名新站点，Google 的首轮抓取通常要几天到两周。复查节奏按周走：第一周看 sitemap 是否被接受、有没有抓取错误；第二周用 URL 检查逐页看「已收录/未收录」；第四周再看展示量是否从 0 动了。连续四周一页未收录，才回头查技术问题（robots 拦截、canonical 错误、内容质量），而不是第一周就推倒重写。

04 收录之后，内容才接上

先铺关键页，再铺长尾

首页、目录页、核心产品页——这三类先确保收录，它们决定站点在搜索里的骨架。长尾文章在骨架稳了之后再加，否则一边写一边改结构，收录信号会被稀释。

内链是第二个管道

被收录不等于有排名：新页面最好在上线当天就被至少一个已被收录的页面链到。新站的第一个内链网络不用复杂——首页 → 关键页 → 新文章，三层就够爬虫走完。

如果只能记一条：新站第一个月的 KPI 是「收录页数」，不是「发文章数」。管道没通，内容都是空转。
